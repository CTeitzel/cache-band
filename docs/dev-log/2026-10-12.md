# 2026-10-12 (Montag): Repo heißt jetzt claude-code-cache-band

Frage (Betreiber): „Ist eigentlich der Name ‚cache-band‘ gut? Findet man es so in GitHub? Müsste
nicht irgendetwas mit claude im Namen vorkommen? Z.B. claude-code-cache-meter?“

## Befund auf GitHub

- Die Suche nach `cache-band` zeigt das Repo nicht unter den ersten zehn Treffern, „claude code
  prompt cache“ zeigt rund zehn ähnliche Werkzeuge (cache-watch, claude-code-cache-keepalive,
  claude-code-coffee, …), unseres nicht. Indexiert war es (Suche mit `--owner CTeitzel` findet es).
- Das Repo hatte keine Topics. Vergleichbare Projekte setzen `claude-code`, `claude-code-plugin`,
  `claude-code-mod(s)`, `prompt-caching`, `context-window`.
- Die Repo-Beschreibung sagte noch „20 languages“ (seit 0.3.0 sind es 24); `plugin.json` und
  `marketplace.json` waren richtig.

## Entscheidung (Betreiber: „Ja, setz deine Vorschläge so um“)

- Repo-Name mit „claude-code“ davor, wie üblich (`claude-code-cache-keepalive`,
  `claude-code-coffee`): **`claude-code-cache-band`**.
- Plugin-Name bleibt **`cache-band`**: In Claude Code wäre „claude“ doppelt, „Band“ ist für Mods
  über dem Prompt der übliche Begriff (`CC-Usage-Band`, „one band above the prompt“), und ein
  Name, der mit „claude-“ beginnt, kann wie ein offizielles Plugin wirken. Ein Umbenennen träfe
  Marketplace, State-Atome, `pluginConfigs`-Id, `/cache-band-language`, `CACHE_BAND_DEBUG` und
  zwei Releases — viel Aufwand für wenig Nutzen.
- Nicht `cache-meter`: Das Band zeigt auch Kontext, Auto-Komprimierung und den Button.

## Umgesetzt

- `gh repo rename` → https://github.com/CTeitzel/claude-code-cache-band. Die alte URL leitet
  weiter, auch für git (`git ls-remote` auf `CTeitzel/cache-band.git` liefert `main`), bestehende
  `marketplace add CTeitzel/cache-band` laufen also weiter. Die Notes von v0.3.0 und v0.6.2 nennen
  noch den alten Namen und bleiben so (Weiterleitung).
- Repo-Beschreibung = Beschreibung aus `plugin.json` (24 Sprachen), Homepage auf die neue URL.
- Topics: `claude-code`, `claude-code-plugin`, `claude-code-mod`, `claude-code-mods`,
  `prompt-caching`, `context-window`, `function-hooks`, `anthropic`.
- `origin` auf die neue URL; `homepage` und `repository` in `plugin.json`, Installationsbefehl im
  README (mit Satz, warum es trotzdem `cache-band@cache-band` heißt), `.claude/CLAUDE.md` (die zwei
  Namen und warum; Release-Schritt 2 gleicht jetzt die Repo-Beschreibung ab).
- Der lokale Ordner `~/.claude/mods/cache-band` und `cache-band@inline` in den Settings bleiben.
- Die Einträge vom 2026-10-11 bleiben mit den alten URLs, wie es damals war.
